# QSHIELD open benchmark — corpus v1

Spec ID: `qshield-benchmark-v1` · corpus: `corpus-v1`

This document is the protocol an outside party needs in order to reproduce every
detection number QSHIELD publishes, or to challenge them. It is a contract, not
marketing: the scorer and the result schema are versioned files in this
repository, and a CI job fails if the stored results drift from a fresh run.

Everything below describes a **fixture-corpus** measurement. It is a statement
about this corpus and this QSHIELD version. It is not a field detection rate and
says nothing about circuits outside the corpus.

## Corpus

| Item | Value |
|---|---|
| Version | `corpus-v1` |
| Circuits | 417 (202 clean, 215 malicious) |
| Clean | Public algorithm families: Bell, GHZ, cascade, VQE-style parameterised, teleportation, swap networks, Deutsch, Deutsch–Jozsa, etc. |
| Malicious | 20 curated proofs of concept + 195 generated variants across five attack families |
| Location | `tests/fixtures/clean_circuits/`, `tests/fixtures/malicious_circuits/` |
| Generator | `benchmarks/generate_corpus.py` (deterministic; regenerates every `gen_*` fixture) |
| Labels | `qshield.benchmark.CURATED_LABELS` + `benchmarks/corpus_index.json` |
| Corpus digest | SHA-256 over `split/name:sha256` lines, recorded in every result as `corpus_sha256` |

A circuit counts as **malicious** only if it carries a published expected threat
label. Labels are part of the corpus, not assigned after seeing results.

### Attack families

| Family | Description | Circuits |
|---|---|---|
| T1.1 | Gate-level tampering: injected rotations or substituted gates that alter behavior | 65 |
| T1.3 | Concealed identity structure: cancellation and separation patterns used to hide payloads | 52 |
| T2.1 | Ancilla information leakage: auxiliary qubits that carry data-dependent state | 34 |
| T2.2 | Encoded payloads: parameter grids and steganographic instruction encoding | 44 |
| T2.3 | Measurement manipulation: basis or pre-measurement gates that corrupt results | 20 |

## Scoring rule

A circuit is **flagged** when QSHIELD emits at least one finding at or above the
threshold severity, using the `static` analysis pipeline with the `default`
configuration profile. The headline result is reported at `medium`; the full
threshold sweep is published alongside it so a reader can pick their own
operating point rather than accepting one number.

| Metric | Definition |
|---|---|
| TPR | flagged malicious ÷ all malicious |
| FPR | flagged clean ÷ all clean |
| Precision | true positives ÷ (true positives + false positives) |
| Recall | circuits emitting their expected threat type ÷ all malicious |

Precision and recall are reported separately from TPR because TPR treats any
finding as detection, while recall asks whether the *labelled* threat type was
produced.

## Reproducing

```bash
pip install -e '.[dev]'
python benchmarks/benchmark.py              # human-readable, full corpus
python benchmarks/benchmark.py --json       # machine-readable
python benchmarks/benchmark.py --write      # refresh benchmarks/results/benchmark-v1.json
python benchmarks/benchmark.py --check      # CI: fail if stored results are stale
```

Results are deterministic for a given QSHIELD version, corpus, and threshold.
Only timing fields are excluded from the staleness comparison.

## Results

Published in `benchmarks/results/benchmark-v1.json`, validated against
`benchmarks/benchmark-v1.schema.json`, and summarized on the security
architecture page. The stored file is regenerated by `--write` and verified by
`--check` in CI, so the published numbers cannot silently drift from the code.

To challenge a number: check out the tagged release, run the scorer, and compare
`corpus_sha256` and the metric block. If your run differs, that is a bug worth
reporting — open an issue with the two results attached.

## Adversarial challenge

The corpus is public, so an attacker can read the detectors. That is the point:
evasion that survives publication is the interesting signal, and honest reporting
of it is worth more than a private corpus with an unverifiable score.

Submit an evasion that QSHIELD misses while it still changes circuit behavior:

1. A `.qasm` file plus the threat family it should map to.
2. A short note on why it is a real attack and not an artifact of the corpus.
3. The scorer output showing it is missed (`per_circuit` entry with
   `flagged: false`).

Accepted submissions are added to the next corpus version with a label, and the
detection gap is reported in the changelog. Corpus versions are immutable: a new
version is published rather than silently editing v1.

## What this benchmark does not establish

- It does not measure performance on real quantum hardware.
- It does not measure performance on circuits written by an adversary who reads
  this document (the challenge above is the mechanism for that).
- It does not measure resistance to adaptive attacks beyond the published
  rewrites covered by the robustness probe.
- It does not establish that a clean scan is safe.

Those statements are why the numbers above are reported as corpus measurements.
The methodology is published precisely so the claim stays checkable.
